# عقد حماية التحليل المساعد

## النطاق

هذا المكوّن يضيف طبقة تحليل مساعد قبل kickoff فقط. لا يغيّر النموذج الكمي، ولا يضيف labels أو نتائج أو odds أو EV أو ROI أو stake sizing، ولا يرسل رسائل إلى Telegram. يظل `commercial_release=false`.

## قواعد الإدخال

يجب أن يحمل كل طلب `match_id` و`kickoff_utc` و`as_of_utc` بتوقيت UTC صريح. يجب أن يسبق `as_of_utc` وقت kickoff. كل معلومة خارجية يجب أن تحمل `evidence_id` واسم المصدر والرابط ووقت الالتقاط وSHA للمحتوى.

لا يرسل الطلب نتائج المباراة أو `matchResults` أو بيانات لاحقة لوقت cutoff. وجود المعلومة في المصدر لا يكفي؛ يجب أن تكون قابلة للإثبات زمنياً.

## قواعد الإخراج

المخرج المقبول هو JSON مطابق تماماً لـ `ai-analysis-v1`. يحتوي على إشارات نوعية مرتبطة بـ`evidence_ids` موجودة في الطلب، أو حالة `insufficient_evidence`. أي حقل زائد أو ناقص، معرف مباراة مختلف، وقت مختلف، ادعاء غير مدعوم، أو مرجع غير موجود يؤدي إلى الرفض fail-closed.

لا يقبل العقد `result` أو `target` أو `odds` أو `ev` أو `roi` أو `stake` أو الأسرار أو tokens. لا يقبل احتمالاً أو توصية مراهنة؛ التوقع الكمي يبقى في النموذج الحالي المنفصل.

## التشغيل

الاختبارات المحلية تستخدم fixtures ثابتة فقط. لم يتم تشغيل نموذج ذكاء اصطناعي على بيانات OpenLigaDB الحية في هذه المرحلة. قبل أول استدعاء حي يجب تحديد النموذج، وتمرير بيانات ما قبل المباراة فقط، وتسجيل إصدار النموذج والتكلفة التشغيلية إن توفرت، ثم حفظ النتيجة في shadow لا في قنوات عامة.

لا يُسمح للمحلل بتعديل الميزات أو النموذج أو policy تلقائياً. المخرجات غير الصالحة تعزل في quarantine ولا تدخل التوقع أو التقييم.

## حالة التحقق

نجحت اختبارات العقد التي تغطي الإشارة المدعومة، المرجع غير المعروف، الادعاءات غير المدعومة، الحقول المحظورة، cutoff غير الصحيح، وحالة نقص الأدلة. يظل اعتماد أي مصدر إضافي للبطاقات أو الأخبار مؤجلاً حتى التحقق المستقل من التغطية والترخيص والحداثة.
