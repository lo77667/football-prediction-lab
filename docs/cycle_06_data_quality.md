# تقرير دورة جودة البيانات السادسة

## النطاق

أضيف فحص جودة مستقل قبل التدريب والتقييم، ثم طُبق على ملف EPL المحلي ذي عشرة مواسم. الفحص لا يعدل البيانات ولا يعوض القيم الناقصة؛ بل يسجل ما إذا كانت العينة صالحة للفحص أو تحتاج إلى توقف.

## نتيجة الفحص الفعلي

| الفحص | النتيجة |
|---|---:|
| الصفوف | 3800 |
| الصفوف ذات معرف مباراة مكرر | 0 |
| فشل تحليل الوقت | 0 |
| الترتيب الزمني في الملف | صحيح |
| الصفوف لكل موسم | 380 |
| نطاق السنوات | 1516–2425 |

سجل الفحص معدلات BTTS حسب الموسم، وظهر تغير واضح بين بعض المواسم؛ فقد بلغ المعدل `0.4895` في `1718` و`2021`، ثم ارتفع إلى `0.6158` في `2324` و`0.5737` في `2425`. هذا تغير وصفي حقيقي في العينة، وليس سببًا لتعديل النتائج أو اختيار النموذج بعد رؤية الاختبار.

## المرور الرقابي

| الشخصية | الإجراء | النتيجة |
|---|---|---|
| المنفذ | بناء `profile_dataset` وأداة التقرير والاختبارات | مكتمل |
| المدقق | تشغيل 47 اختبارًا وRuff وفحص الملف الكامل | ناجح |
| المراجع | التأكد من أن الفحص تشخيصي ولا يقوم بالـimputation أو اختيار النموذج | مطابق |
| الباحث | التعامل مع معدلات المواسم بوصفها وصفًا للعينة لا ادعاءً سببيًا | سليم |
| المطور | اقتراح استخدام فحص التغير قبل كل دورة تدريب | منفذ |
| الضامن | مراجعة نظافة الفرع وعدم رفع البيانات الكبيرة | قيد الإكمال قبل الدفع |

## القرار

تُقبل أداة فحص الجودة، ويجب تشغيلها قبل المقارنات المستقبلية. لا تعني سلامة المعرفات والتوقيت أن النموذج صالح أو مربح؛ إنها فقط تمنع أخطاء المصدر والملف من الاختلاط بأداء النموذج.

## حساسية طول التاريخ التدريبي

أضيفت تجربة وصفية على holdout موسم `2425` تقارن آخر 3 مواسم، وآخر 5 مواسم، وكل المواسم السابقة. في BTTS، كانت قيم Brier/Log Loss على الترتيب: آخر 3 `0.2565/0.7069`، آخر 5 `0.2492/0.6922`، وكل السابق `0.2541/0.7023`. وفي البطاقات legacy كانت: آخر 3 `0.2437/0.6802`، آخر 5 `0.2420/0.6772`، وكل السابق `0.2425/0.6780`.

هذه مقارنة حساسية على holdout واحد وليست قاعدة اختيار إنتاجية؛ لا يجوز اختيار نافذة التدريب بعد رؤية موسم الاختبار ثم إعلان أداء غير متحيز. ستُستخدم هذه النتائج لتصميم walk-forward لاحق يختار النافذة من validation فقط.
