# تقرير دورة التطوير السادسة

## النطاق

أضافت الدورة فحص جودة قبل التدريب، وتجربة حساسية لطول التاريخ، وتشديدًا نهائيًا لهوية مصدر الأحداث النوعية. بقيت البيانات الخام والمعالجة وتقارير generated خارج Git، وبقي المشروع خاصًا وبحثيًا.

## جودة العينة

على ملف EPL المحلي ذي عشرة مواسم، بلغ عدد الصفوف 3800، وعدد معرفات المباريات المكررة صفرًا، وفشل تحليل الوقت صفرًا، وكان ترتيب `kickoff_utc` صحيحًا. بلغ عدد الصفوف 380 لكل موسم. سجل الفحص معدلات BTTS حسب الموسم لاستخدامها في تشخيص تغير التوزيع، دون تعديل النتائج أو اختيار الاختبار بعد الاطلاع عليه.

## حساسية طول التاريخ

على holdout موسم `2425`، قورنت نوافذ آخر 3 مواسم، وآخر 5، وكل المواسم السابقة. في BTTS كانت Brier/Log Loss: `0.2565/0.7069`، ثم `0.2492/0.6922`، ثم `0.2541/0.7023`. وفي البطاقات legacy كانت `0.2437/0.6802`، ثم `0.2420/0.6772`، ثم `0.2425/0.6780`. هذه مقارنة وصفية على holdout واحد؛ لا تُستخدم لاختيار نافذة إنتاجية بعد رؤية الاختبار.

## provenance

أصبح تطابق `source_id` و`source_url` بين الحدث وprovenance إلزاميًا، إلى جانب وقت الإتاحة والحقوق وSHA-256. رُفضت حالات عدم التطابق آليًا، وبلغ مجموع الاختبارات 48. أي حدث بلا provenance يمكن أن يبقى في سجل المراجعة، لكنه لا يدخل الميزات التدريبية.

## قرار الأدوار

| الشخصية | القرار |
|---|---|
| المنفذ | نفذ فحص الجودة وتجربة الحساسية وتشديد provenance |
| المدقق | 48 اختبارًا، Ruff، compileall، وفحص CI ناجح |
| المراجع | أكد أن holdout لم يُستخدم لاختيار النافذة |
| الباحث | أبقى الأحداث النوعية غير الموثقة خارج التدريب |
| المطور | أوصى بجعل جودة الملف شرطًا سابقًا لكل تجربة |
| الضامن | راجع نظافة `main` ونجاح GitHub Actions |

## الخلاصة

تُقبل أدوات التشخيص والحماية. لا يوجد دليل على تحسن عام أو ربحية. ينبغي أن تظل كل نافذة أو ميزة مرشحًا بحثيًا إلى أن تتفوق في walk-forward مستقل وعلى معدل التدريب الثابت، مع فواصل عدم يقين وتوثيق provenance كامل.
