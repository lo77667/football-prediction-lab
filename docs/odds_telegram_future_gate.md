# بوابة odds وTelegram المستقبلية

## الحالة الحالية

أضيف `adapt_odds_payload` كـfixture-only adapter. لا يفتح اتصالاً شبكياً ولا يختار مزوداً حياً، ويتحقق من هوية المباراة، ووقت kickoff الموثوق، ووقت الالتقاط قبل kickoff، وحقوق إعادة الاستخدام، وحقول odds الكاملة. أي صف غير صالح يُرفض ولا يُحتسب.

توجد أيضاً طبقة Telegram آمنة من الدورات السابقة. وضعها الافتراضي `dry_run`، والعميل الحقيقي معطل، مع Fake client للاختبارات، ومنع التكرار وretry محدود وdead-letter وkill switch. أُضيف اختبار يؤكد عدم ظهور odds أو EV أو ROI أو stake في الرسائل.

## شروط التفعيل المستقبلي

لا يُفعّل مزود odds حي قبل توثيق اسم المزود، endpoint، الترخيص أو سياسة إعادة الاستخدام، التغطية، حد الطلبات، freshness، وتوقيع كل snapshot مع provenance. يجب أن تبقى snapshots قبل kickoff فقط، وألا تدخل النموذج إلا عبر قرار منفصل واختبارات منع تسرب.

لا يُفعّل Telegram الحقيقي قبل إنشاء قناة اختبار، وضع token في GitHub Secrets خارج المستودع العام، تشغيل dry-run، اختبار recipient وkill switch، ومراجعة بشرية صريحة. لا يُرسل أي تنبيه من workflow الحالي؛ فهو يجمع OpenLigaDB فقط.

## الممنوعات الحالية

لا توجد odds حية، ولا EV أو ROI أو stake sizing، ولا توصيات مراهنة، ولا Telegram حقيقي، ولا تعديل تلقائي للنموذج. تبقى الحالة `shadow_only` و`commercial_release=false`.

## معيار القبول

نجحت اختبارات odds وTelegram الحالية معاً، ويجب إعادة تشغيل المجموعة الكاملة وquality-gate البعيد بعد كل تغيير. نجاح الاختبارات يثبت سلامة العقود والتنفيذ، ولا يثبت الربحية أو الدقة التجارية أو ملاءمة أي مصدر odds.
